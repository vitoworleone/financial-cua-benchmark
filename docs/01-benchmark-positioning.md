# 金融 Agent 任务设计方法

## 从生成结果到完成任务

金融任务的评价不能停留在“文档是否像成品”。一份可接受的结果需要同时满足：主体、期间、口径、单位、字段、业务公式、来源依据和最终状态都正确。

因此，本项目把金融 Agent 的工作描述为：在规定环境中读取输入、完成业务处理、写入目标系统或结构化交付物，并留下可复核结果。

## 任务合同

每个任务在实现前先定义以下合同：

```text
业务目标
→ Agent 可见输入与操作约束
→ 初始环境状态
→ 必交产物与最终状态
→ 正确结果的计算方式
→ Verifier 与人工复核分工
```

这套合同同时服务于任务设计、环境准备、测试实例构造和评分实现，确保业务目标、输入和评分规则保持一致。

## 设计原则

### 业务状态优先

重点验证最终业务状态：表单是否真正提交、字段是否落在正确位置、工作底稿是否形成结构化结论。Agent 可以采用不同的合规操作路径。

### 确定性规则优先

数值、单位、期间、公式、匹配关系和状态优先由程序判断。只有披露充分性、材料充分性、专业判断等无法完全形式化的部分，才进入人工复核。

### 来源可追溯

每个重要字段应能定位到来源文件、行列、页码、规则或计算过程。正确数值没有来源依据，不能视为完整交付。

### 红线清晰

错误主体、错误期间、整体单位错误、关键勾稽失败、未正式提交和输入篡改属于不同严重程度的失败，并在 Verifier 中通过门禁或封顶显式表达。

### 人机协作边界

Agent 用于材料整理、计算、核对、初稿和异常提示；专业判断、正式结论和外部责任仍由业务人员承担。
