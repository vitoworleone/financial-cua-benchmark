# 校验项说明：Verifier 到底在检查什么

`Checker ID` 是 Verifier 内部使用的稳定编号。它不是抽象术语，每一个编号都对应一项可以说明、可以复算的业务检查。

编号通常由两部分组成：

```text
检查类别.具体对象或业务规则
```

例如，`RULE.BS.BALANCE` 表示“业务规则（RULE）—资产负债表（BS）—平衡关系（BALANCE）”。

## 通用校验项

| Checker ID | 校验什么 | 为什么需要它 | 失败意味着什么 |
| --- | --- | --- | --- |
| `META.IDENTITY` | 任务 ID、主体、报告期间和报表口径是否与任务要求一致 | 同一组数字换了主体、期间或合并口径，业务含义可能完全不同 | Agent 在错误对象上完成了工作，结果不能作为正确交付 |
| `META.UNIT` | 填报单位是否已声明且可转换，如元、千元、万元 | 单位错一次，所有金额可能整体放大或缩小 10,000 倍 | 数字表面正确但实际金额错误，需要封顶处理 |
| `SECURITY.INPUT_INTEGRITY` | 任务输入是否保持初始哈希，是否触发隐藏信息读取、后台篡改等安全标记 | 评测必须基于给定材料完成，不能修改材料或绕过规则 | 属于安全失败，结果记为 `HACK` 并归零 |
| `OUTPUT.COMPLETENESS` | 必交文件、manifest 或说明是否存在 | 完成业务不只是填几个数字，还要交付可复核产物 | 任务交付不完整，不能视为完成 |
| `FIELD.CRITICAL` | 关键字段是否与正确值一致 | 资产总计、现金余额、关键税额等错误会直接改变结论 | 关键业务结果错误，通常触发较严格封顶 |
| `FIELD.NONCRITICAL` | 其他适用字段是否正确 | 不能只靠关键合计正确就掩盖大量明细错误 | 影响完整性和基础分，但可保留可诊断的部分分数 |
| `PROVENANCE.FIELD_MAP` | 每个重要结果是否保留来源文件、位置或计算依据 | 财务工作需要让复核人知道数字从哪里来 | 结果不可追溯，无法支持复核或责任留痕 |
| `STATE.SUBMITTED` | 后端或目标系统的最终状态是否为 `submitted` | 保存草稿、截图显示成功和正式提交是不同状态 | Agent 未真正完成目标操作 |

## 资产负债表校验项

| Checker ID | 校验什么 | 业务意义 |
| --- | --- | --- |
| `RULE.BS.BALANCE` | 资产总计 = 负债总计 + 所有者权益总计 | 最基本的资产负债表平衡关系；不平衡说明填报或计算存在实质错误 |
| `RULE.BS.ASSET_SUBTOTALS` | 资产总计 = 流动资产合计 + 非流动资产合计 | 检查资产分类汇总是否完整，防止明细遗漏或错位 |
| `RULE.BS.LIABILITY_SUBTOTALS` | 负债总计 = 流动负债合计 + 非流动负债合计 | 检查负债分类汇总是否完整，防止明细遗漏或错位 |

即使三条公式全部通过，Verifier 仍会执行字段真值和来源检查：两个错误数字恰好相互抵消，不能因为“表平了”就判为正确。

## 现金流量表校验项

| Checker ID | 校验什么 | 业务意义 |
| --- | --- | --- |
| `RULE.CF.NET_CHANGE` | 现金净变动 = 经营活动 + 投资活动 + 筹资活动现金流 | 检查三类现金流是否共同解释当期现金变动 |
| `RULE.CF.CASH_ROLLFORWARD` | 期末现金 = 期初现金 + 现金净变动 | 检查现金余额在两个期间之间是否连续、可解释 |

## 融资租赁摊还表校验项

| Checker ID | 校验什么 | 业务意义 |
| --- | --- | --- |
| `CONVENTION.ACT360` | 年利率、实际天数和分母是否采用 ACT/360 计息约定 | 计息约定不同会系统性改变每期利息 |
| `PERIOD.COMPLETENESS` | 付款期次是否齐全且连续 | 少一期或期次错位会使整张 schedule 失效 |
| `PERIOD.DATES_AND_DAYS` | 付款日期与实际天数是否可由起租日和上一付款日复算 | 避免人为写入错误天数或错用固定天数 |
| `RULE.ACT360_INTEREST` | 利息是否按期初本金、年利率、实际天数和 360 重算 | 验证实际利率法核心计算 |
| `RULE.PRINCIPAL_INTEREST_SPLIT` | 实收现金 = 利息 + 本金 | 验证每期收款的本息拆分 |
| `RULE.PERIOD_ROLLFORWARD` | 期末本金 = 期初本金 − 本金，且下一期期初承接上期期末 | 验证整张表逐期连续而非每行各自成立 |
| `RULE.TOTALS_AND_RESIDUAL` | 汇总现金、利息、本金和最终余额与逐期结果一致 | 验证汇总层和残值处理 |

## 分数与校验的关系

校验器先生成基础分，再应用业务红线：

```text
基础分：通过项的权重之和
最终分：基础分经过关键字段、公式、身份、单位、提交和安全门禁后的结果
```

因此，一项公式校验失败不只是“扣一点分”；当它破坏关键业务关系时，会阻断通过或限制最终得分。任务级规则详见各任务包的 `verifier.md`。
