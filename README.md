# Financial CUA Benchmark｜金融 Computer-Use Agent 评测框架

> 评估金融 Agent 是否真正完成可复核的工作，而不只是生成一份“看起来正确”的财务文件。

这是一个面向中文金融场景的 Computer-Use Agent（CUA）任务与验证器项目。项目将财务会计任务、确定性 Verifier 架构，以及债券承做工作流设计放在同一套评测模型中。

## 项目状态：重构中，中文优先

源工作区有大量任务草稿、规则设计和验证器原型；本仓库不会整包搬运，而是逐项审阅、重构后公开。目前已有三类证据：

| 证据层级 | 当前已有内容 | 不能据此宣称的结论 |
| --- | --- | --- |
| 任务设计 | 20 个标准财务会计任务的源设计，以及 6 个债券承做工作流设计 | 任务已在生产式 Agent 环境端到端运行 |
| 验证器 | 旧框架有 21 个注册模块；新公开核心已独立重构资产负债表、现金流量表和 ACT/360 租赁摊还表三类 Verifier | 已建立公开/私有测试集，或已完成真实 Agent 评测 |
| 测试 | 公开核心目前有 10 个纯合成测试；旧框架留有代表性对抗探针记录 | 全任务覆盖的对抗测试或模型排行榜 |

除非有可复现实验协议和运行产物，本仓库不会发布模型排行榜、通过率或端到端 Agent 成绩。

## 到底评什么

每个任务都被表示为可验证的状态转移：

```text
(t, c, s_init, s_gold, r)
```

| 元素 | 含义 |
| --- | --- |
| `t` | Agent 可见的任务指令 |
| `c` | 有边界的上下文：主体、期间、文件、政策、输出合同与限制 |
| `s_init` | 可复现的初始环境状态 |
| `s_gold` | 与 Agent 可见材料隔离的正确最终业务状态 |
| `r` | 根据最终可观察状态输出有界分数的验证器 |

目标不是证明 Agent 可以替代金融专业人员，而是对其中可控制、可审阅的工作环节进行评估：结构化填报、勾稽、规则适用、跨文件核对、证据映射和底稿初稿准备。

## 设计原则

1. **确定性判分优先。** 数值、公式、单位、期间、完成状态与可观察业务状态优先用确定性规则检查。
2. **看最终业务状态，不强制点击轨迹。** 评估 Agent 最终产出了什么、是否真正提交，而不是要求唯一工具路径。
3. **数值正确还不够，必须能追溯。** 正确合计但没有字段到来源的映射，不能算满分。
4. **渐进得分，但保留真实红线。** 字段覆盖可获得部分得分；错主体、错期间、篡改输入、未提交或关键勾稽失败会触发封顶或失败。
5. **保留人的责任边界。** 专业判断、正式结论和真实外部提交始终由人承担。
6. **公开开发集与私有 holdout 分离。** 公开示例只使用合成或明确授权发布的开发实例；答案与测试实例独立管理。

## 当前已经完成的重构

- 资产负债表填报：字段真实性、单位、主体/期间/口径、三项表内勾稽、来源映射和提交状态。
- 现金流量表填报：三类现金流、现金净变动、期初期末滚动、来源映射和提交状态。
- 融资租赁 ACT/360 摊还表：由实例注入条款和现金流，Verifier 仅保留实际天数、利息、拆分、滚动与汇总规则。

在仓库根目录运行即可验证公开测试：

```powershell
python -m pytest
```

当前结果为 `10 passed`。这证明的是公开 Verifier 核心的合成测试，而不是模型成绩。
