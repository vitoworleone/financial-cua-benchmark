# `fin_d2_cash_flow` Verifier 合同

实现位置：`verifier/src/finbench/tasks/cash_flow.py`。每个 Checker ID 的中文含义见[校验项说明](../../docs/04-checker-guide.md)。

| 校验项 | 校验内容 | 业务意义 | 权重 |
| --- | --- | --- | ---: |
| `META.IDENTITY` | 任务 ID、主体、期间、口径一致 | 防止把正确现金流填入错误主体、期间或合并范围 | 0.06 |
| `META.UNIT` | 单位已声明且受支持 | 防止元、千元、万元换算导致整体金额偏差 | 0.04 |
| `SECURITY.INPUT_INTEGRITY` | 输入哈希与安全标记通过 | 确保现金流结果基于规定输入生成，未绕过任务边界 | 门禁 |
| `OUTPUT.COMPLETENESS` | 必要输出产物齐全 | 确保表单、提交清单等交付物可被复核 | 0.04 |
| `FIELD.CRITICAL` | 指定关键现金字段等于正确值 | 确保经营、投资、筹资净额及现金余额等核心结果可靠 | 0.30 |
| `FIELD.NONCRITICAL` | 其他预期字段等于正确值 | 防止只填对合计、遗漏或填错明细 | 0.28 |
| `RULE.CF.NET_CHANGE` | 净变动 = 经营 + 投资 + 筹资 | 验证三类现金流能完整解释当期现金变动 | 0.09 |
| `RULE.CF.CASH_ROLLFORWARD` | 期末现金 = 期初现金 + 净变动 | 验证现金余额在期间之间连续、可解释 | 0.07 |
| `PROVENANCE.FIELD_MAP` | 每个预期字段有来源映射 | 让复核人可以追溯现金流数字的来源或计算依据 | 0.08 |
| `STATE.SUBMITTED` | 后端状态为 `submitted` | 区分正式提交与仅保存、仅导出或仅生成文字说明 | 0.04 |

错主体上限 0.55，错单位上限 0.70，关键字段错误上限 0.65，任一现金桥失败为 0，未提交上限 0.40。输入篡改或访问评测器状态则为 0 分并标为 `HACK`。

合成测试覆盖 golden、空白状态和现金桥断裂。源设计中的直接/间接法勾稽、汇率影响、非现金事项和受限资金政策，只有在拥有独立公开合成 fixture 后才会纳入。
